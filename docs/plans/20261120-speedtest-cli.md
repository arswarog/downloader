# speedtest.mjs — замер скорости скачивания (Node.js CLI)

Дата: 2026-11-20. Статус: реализовано и проверено (см. «Результаты проверки»).

## Цель

Консольный скрипт на Node.js: принимает URL (например, тяжёлую картинку), делает 10
последовательных запросов с полным вычитыванием тела каждого, печатает суммарный объём,
среднее время запроса и агрегатную скорость скачивания.

## Согласованные решения

| Вопрос | Решение |
|---|---|
| Метрика скорости | агрегат: `Σбайт / Σвремени` успешных запросов |
| Поставка | `speedtest.mjs` + `README.md`; без `package.json`, без зависимостей, ESM, Node ≥ 18 |
| Учёт байт | браузерный профиль: `fetch` без подмены `Accept-Encoding`; считаются байты, прочитанные из тела (т.е. распакованные); сверки с `Content-Length` нет |
| Прогресс | строка на запрос только по `-v` / `--verbose` |
| Ошибки запросов | все 10 попыток выполняются; не-2xx/сетевые упавшие исключаются из статистики; ретраев нет |
| Единицы | скорость в MiB/s (основная) и MB/s в скобках; объём в MiB; время в ms/s |
| Не делаем | min/max, JSON-вывод, флаг числа запросов, ретраи, прогрев соединения |

## CLI

```
node speedtest.mjs <url> [-v|--verbose] [-h|--help]
```

* ровно один позиционный аргумент; лишние → ошибка (exit 1);
* URL валидируется `new URL()`, допустимы только `http:`/`https:`;
* `--help` → usage, exit 0;
* число запросов фиксировано: 10.

## Агрегаты

По успешным запросам `i`: `d_i` — от `performance.now()` перед `fetch` до конца тела, `b_i` — байты.

* `totalBytes = Σ b_i`
* `totalWall = Σ d_i` — время упавших попыток в знаменатель не входит (иначе таймаут занизил бы скорость); при 10/10 отличается от настенного времени серии только на паузы между итерациями (доли мс)
* `avgRequest = mean(d_i)`
* `speed = totalBytes / (totalWall / 1000)`

Единицы: `1 MiB = 1024²`, `1 MB = 10⁶`, `Мбит/с = MiB/s × 8 × 1.048576`.

## Вывод

```
URL:         https://example.com/big.jpg
Runs:        10 (sequential)

Total:       48.83 MiB
Wall time:   3.942 s
Avg request: 394 ms
Speed:       12.39 MiB/s (12.99 MB/s)
Succeeded:   9/10
```

`Succeeded` печатается всегда. Упавшие запросы — в stderr: `#05 failed: HTTP 503 Service Unavailable`.
Если успешных 0 — сводка не печатается.

Коды выхода: `0` — все 10 успешны; `2` — частичный успех; `1` — фатально (аргументы/URL) или 0 успешных.

## Шаги

1. `speedtest.mjs`
   - разбор аргументов и валидация URL, `usage()`, `fail()` → exit 1;
   - `measure(url)`: `fetch` → не-2xx ⇒ отменить тело и вернуть ошибку → иначе вычитать тело
     потоком (`for await`), суммируя `byteLength`, чанки не накапливать; ошибки `fetch`
     дополнять `err.cause.code`;
   - цикл 10 итераций, `-v` печатает `#NN  X.XX MiB  NNN ms`;
   - агрегаты по успешным, сводка, `process.exitCode`.
   - Acceptance: скрипт запускается на локальном сервере; объём равен 10 × размер файла;
     exit-коды соответствуют таблице.
2. `README.md`: запуск, флаги, пример вывода, таблица единиц, методика/ограничения
   (последовательные запросы, keep-alive, распакованные байты, таймауты undici 300 s,
   fail-continue без ретраев, исключение упавших из статистики, коды выхода).
3. Проверка (throaway-сервер в `/tmp`, в репозиторий не коммитится):
   - 200 + 5 MiB файл → `Total: 50.00 MiB`, `Succeeded: 10/10`, exit 0;
   - gzip-ответ → счётчик байт равен размеру несжатого файла;
   - 503 на 3-м запросе → `Succeeded: 9/10`, exit 2;
   - все 404 → сводки нет, exit 1; неверные аргументы → exit 1;
   - `-v` → 10 строк прогресса;
   - реальный тяжёлый URL → осмысленные MiB/s.

## Риски

* Цифра «тёплая»: undici переиспользует keep-alive соединение между последовательными запросами (как браузер), cold-start медленнее — оговорено в README.
* Таймаут задаёт undici (300 s headers/body), своего кода нет — зависший сервер завершится ошибкой, а не вечным ожиданием.

## Результаты проверки (2026-11-20)

Локальный `node:http`-сервер (throwaway, `/tmp`), Node v24.21.0:

| Сценарий | Наблюдение |
|---|---|
| 200, файл 5 MiB × 10 | `Total: 50.00 MiB`, `Succeeded: 10/10`, exit 0 |
| gzip-ответ (5 MiB → ~5 KiB по сети) | `Total: 50.00 MiB` — считаются распакованные байты, как и задумано |
| 503 на 3-м запросе | `#03 failed: HTTP 503 Service Unavailable`, `Total: 45.00 MiB`, `Succeeded: 9/10`, exit 2 |
| все 404 | 10 строк в stderr, сводки нет, exit 1 |
| соединение отклонено (`127.0.0.1:1`) | `fetch failed (bad port)` ×10, exit 1 |
| пустое тело 200 / 204 | `Total: 0.00 MiB`, предупреждение, exit 0 |
| неверные аргументы (нет URL, `ftp:`, мусор, лишний аргумент, `--bogus`) | сообщение + exit 1 |
| `--help` | usage, exit 0 |
| `-v` | ровно 10 строк `#NN`, числа совпадают с итогом |

Реальная сеть:

* `https://upload.wikimedia.org/.../Fronalpstock_big.jpg` (14.0 MiB) — Wikimedia ответила
  `429 Too Many Requests` на все 10 попыток; скрипт корректно завершился с exit 1 без сводки.
* `https://speed.cloudflare.com/__down?bytes=20000000` — `Total: 190.73 MiB`
  (= 10 × 20 000 000 байт, сходится точно), `Speed: 9.19 MiB/s (9.63 MB/s)`, exit 0.
