# speedtest

Консольный скрипт на Node.js: скачивает указанный URL 10 раз подряд, каждый раз дочитывая
тело ответа до конца, и печатает суммарный объём, среднее время запроса и скорость скачивания.

## Требования

Node.js ≥ 18 (используются встроенные `fetch` и Web Streams). Проверено на Node 24.
Зависимостей нет, `npm install` не нужен.

## Запуск

```bash
node speedtest.mjs <url>              # итоговая сводка
node speedtest.mjs <url> -v           # плюс строка на каждый запрос
node speedtest.mjs --help
```

Флаги:

| Флаг | Значение |
|---|---|
| `-v`, `--verbose` | печатать `#NN  объём  время` после каждого завершённого запроса |
| `-h`, `--help` | показать справку |

Количество запросов фиксировано: 10.

## Пример вывода

Реальный прогон (20 MB payload, 10 запросов):

```
URL:         https://speed.cloudflare.com/__down?bytes=20000000
Runs:        10 (sequential)

Total:       190.73 MiB
Wall time:   20.766 s
Avg request: 2077 ms
Speed:       9.19 MiB/s (9.63 MB/s)
Succeeded:   10/10
```

С `-v` перед сводкой появляются строки прогресса:

```
#01  19.07 MiB  2481 ms
#02  19.07 MiB  2473 ms
#03  19.07 MiB  1927 ms
...
```

Если часть запросов упала, они уходят в stderr, а сводка показывает неполную выборку:

```
#03 failed: HTTP 503 Service Unavailable
URL:         http://127.0.0.1:33261/flaky
...
Total:       45.00 MiB
...
Succeeded:   9/10
```

## Единицы

| Величина | Единица | Определение |
|---|---|---|
| Скорость (основная) | **MiB/s** | байт/с ÷ 1024² |
| Скорость (в скобках) | MB/s | байт/с ÷ 10⁶ |
| Объём | MiB | 1024² байт |
| Время | ms, s | миллисекунды, секунды |

Пересчёт: `1 MiB/s = 1.048576 MB/s = 8.388608 Мбит/с` (провайдеры обычно считают в Мбит/с).

## Как считается скорость

Скорость — агрегатная: суммарный объём успешных запросов делится на суммарное время этих
же запросов.

* `Total` — сумма байт по успешным запросам;
* `Wall time` — сумма длительностей успешных запросов (от старта `fetch` до последнего байта
  тела). Паузы между итерациями и время упавших запросов в знаменатель не входят;
* `Avg request` — среднее арифметическое длительностей успешных запросов;
* `Speed` — `Total / Wall time`.

## Ошибки

* Все 10 попыток выполняются всегда. Упавший запрос (не-2xx, сетевая ошибка, таймаут)
  печатается в stderr (`#05 failed: HTTP 503 Service Unavailable`) и **исключается** из
  статистики. Ретраев нет — число попыток остаётся равным 10.
* Если успешных запросов 0 — сводка не печатается.
* Коды выхода: `0` — все 10 успешны; `2` — частичный успех (≥ 1 запрос упал);
  `1` — фатальная ошибка (аргументы, URL) или ни одного успешного запроса.
* `Succeeded: N/10` печатается всегда, чтобы неполная выборка не была скрытой.

## Методика и ограничения

* Запросы строго последовательные; общий dispatcher undici переиспользует соединение
  (keep-alive), как браузер. Это цифра «тёплого» соединения, не cold-start.
* Считаются байты, прочитанные из тела, то есть **распакованные**: `fetch` сам декодирует
  `gzip`/`deflate`/`br`, если сервер их отдал. `Content-Length` описывает сжатый поток и не
  сверяется; тело читается потоком и не накапливается в памяти, поэтому размер файла не
  ограничен доступной памятью.
* Редиректы проходятся автоматически (до 20); время цепочки входит в длительность запроса,
  байты считаются только у финального тела.
* Своего таймаута нет: действуют дефолты undici (`headersTimeout` и `bodyTimeout` — 300 с),
  поэтому зависший сервер завершится ошибкой, а не вечным ожиданием.
